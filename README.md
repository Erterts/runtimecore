# R3E (Runtime Radar Resilience Engine)
**Высокопроизводительное C++23 ядро потоковой реконструкции динамических графов и детерминированного управления памятью.**

Репозиторий содержит текущий архитектурный срез и реализацию системного конвейера обработки потоковой телеметрии в реальном времени. Проект служит экспериментальной базой для исследования компромиссов пространственной локальности данных, полиморфных аллокаторов (`std::pmr`) и алгоритмов отложенного связывания с константной сложностью.

---

### Ключевые архитектурные решения

* **Zero-Copy межпроцессный транспорт (`tmpfs` / `mmap`):** Полный отказ от сетевого стека на горячем пути. На Linux входной поток проецируется напрямую из оперативной памяти (`/dev/shm`) в адресное пространство процесса через `mmap` с ожиданием событий по `inotify` (без выделения промежуточных строковых буферов). Выходные дельты публикуются через атомарный `rename()`.
* **Двухконтурное кэширование и PMR-арены (`std::pmr`):** Разделение хранения на узловой каркас топологии (`boost::unordered_node_map`) для гарантии стабильности ссылок и плоский архив метаданных (`boost::unordered_flat_map`) с открытой адресацией для минимизации промахов кэша CPU (L1/LLC). Память выделяется из изолированных по потокам монотонных буферов (`std::pmr::monotonic_buffer_resource`), что исключает системные вызовы `malloc/free` и фрагментацию кучи.
* **Отложенное связывание за $O(1)$ (`Bucket-Wheel`):** При нарушении причинно-следственного порядка доставки событий (out-of-order events) «узлы-призраки» регистрируются в циклическом таймере на **256 временных корзин** с ленивым удалением (*Lazy Cancellation*), что устраняет линейное сканирование графа и устраняет p99-latency.
* **Многопоточный конвейер (Producer / Consumer):** Чтение потока, SIMD-валидация синтаксиса (`simdjson`), графовый анализ (`BFS` с ограничением радиуса риска) и периодическая сериализация дельт (`DeltaCache`) разнесены по независимым потокам.
* **Кольцевой бэкап состояния (`SnapshotRing`):** Циклический буфер на 150 слотов сохраняет слепки легкого графа с шагом 2 секунды, обеспечивая константный расход памяти и поддержку отката состояния во времени (`History Mode`).

### Структура проекта

* `/src/main.cpp` — точка входа и координация многопоточного конвейера.
* `/include` — заголовочные файлы и реализации модулей ядра:
  * `graph_struct.hpp`, `globals.hpp` — двухконтурная модель памяти, структуры `LiteInfo` / `FatInfo` и конфигурация PMR-арен.
  * `json_io.hpp`, `upsert_lite.cpp`, `helpers.cpp` — SIMD-разбор потока (`simdjson`) и обновление топологии.
  * `flag_change.hpp` — кольцевой таймер отложенного связывания на 256 бакетов.
  * `detect.hpp`, `detect.cpp`, `detect_state.hpp` — выделенный воркер аналитики, правила детекта и итеративный BFS.
  * `delta_cache.hpp`, `delta_cache.cpp`, `snapshot.hpp`, `snapshot.cpp` — генератор инкрементальных дельт и кольцевой буфер слепков.
  * `tmpfs.hpp`, `tmpfs_linux.cpp`, `tmpfs_win.cpp` — кроссплатформенный слой работы с разделяемой памятью.
* `/documents/ARCHITECTURE.md` — подробное описание архитектуры и вектора масштабирования.
* `CMakeLists.txt` — сценарий сборки проекта.

### Сборка проекта (CMake)

Сборка полностью автоматизирована: при первой конфигурации `CMakeLists.txt` самостоятельно загружает и подключает все необходимые библиотеки через `FetchContent` (`Boost.Unordered 1.92.0`, `simdjson 5.1.1`, `RapidJSON 1.1.0`). 

**Требования:** `CMake >= 3.15`, компилятор с поддержкой стандарта **C++23** (`GCC 13+` / `Clang 16+` / `MSVC`) и доступ в интернет при первом запуске конфигурации.

#### Linux (GCC / Clang)
```bash
git clone https://github.com/Erterts/runtimecore.git
cd <имя-папки-репозитория>
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
```
После сборки в директории `build/` появятся два исполняемых файла: `runtimecore` (основное ядро) и `run_tests` (модульные тесты).

#### Windows (MinGW / g++)
```powershell
git clone https://github.com/Erterts/runtimecore.git
cd <имя-папки-репозитория>
cmake -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```
Исполняемый файл: `build\runtimecore.exe`

### Подготовка файловой системы перед запуском

Ядро ожидает наличие директории разделяемой памяти для чтения входного потока событий и атомарной записи выходных дельт (`delta.json`).

#### На Linux (`/dev/shm`)
При запуске на Linux ядро по умолчанию использует системный раздел в оперативной памяти `/dev/shm` и автоматически создает входной файл `tetragon.log`, если он отсутствует. При необходимости пути можно переопределить через переменные окружения:
```bash
export RR_SHM_IN="/dev/shm/radar_in"
export RR_SHM_OUT="/dev/shm/radar_out"
export RR_LOG_FILE="tetragon.log"

./build/runtimecore
```

#### На Windows (Эмуляция через NTFS)
Перед запуском `runtimecore.exe` необходимо создать рабочую директорию, задать переменную окружения `RR_SHM` (иначе будет использована стандартная папка `%TEMP%\rr_shm`) и создать пустой входной файл логов `tetragon.log` в кодировке UTF-8:
```powershell
mkdir C:\dev\radar\shm -Force
\$env:RR_SHM = "C:\dev\radar\shm"
New-Item -Path "\$env:RR_SHM\tetragon.log" -ItemType File -Force

.\build\runtimecore.exe


# В случае, если не заданы переменные окружения в сессии, или происходят неизвестные ошибки:

# 1. Задаём единую переменную пути и создаём папку-эмулятор tmpfs
$shmDir = "C:\dev\runtimecore\shm"
New-Item -Path $shmDir -ItemType Directory -Force | Out-Null

# 2. Прокидываем переменные окружения (совпадают с конфигом в tmpfs_win.cpp)
$env:RR_IN_DIR  = $shmDir
$env:RR_OUT_DIR = $shmDir
$env:RR_IN_FILE = "tetragon.log"

# 3. Создаём чистый пустой входной лог без BOM
New-Item -Path "$shmDir\tetragon.log" -ItemType File -Force | Out-Null

# 4. Запускаем скомпилированное ядро
.\build\runtimecore.exe

```
