2. Логика ядра 
---------------------------------------------------------------------
Ловим изменения tmpfs и берём оттуда сырой лог
Проверяем целостность пакета по контрольной сумме fletcher32
Собираем 2 хранилища в параллельных потоках: 
- std::unordered_map по ключу pid - легкая версия, достаточная для создания графа. в ней храним тип события,ppid,gppid(родительский процесс для родителя, достаётся за O(1)),timestamp
- boost::unorderet_flat_set по ключу exec_id- сюда раскрываем полностью входящий json по структурам graph_struct.hpp с помощью json_io.hpp
Запускаем блок детекта ИБ атак, там же расставляем флаг зараженного процесса и флаги in_risk для проессов, связанных с зараженным
Раз в 100мс формируем json изменений с помощью delta_cache 
Раз в 2с кэшируем слепок графа с помощью snapshot.hpp в кольцевой буфер

Весь обмен данными с DevOps и front частями идет через tmpfs
