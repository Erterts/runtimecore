Создай современный, отзывчивый веб-дашборд в стиле кибербезопасности (SOC / EDR мониторинг в реальном времени) для визуализации графа процессов Linux от C++23 ядра R3E (Runtime Radar Resilience Engine).

### 1. Стек технологий
- React + TypeScript (Vite)
- Tailwind CSS (тёмная тема в стиле Dark Slate / Cyberpunk SOC: фон #0b0f19, карточки #111827, акценты неоново-синий, изумрудный, янтарный, алый)
- Cytoscape.js (для отрисовки направленного графа процессов)
- Lucide-react (иконки)

### 2. Контракт данных (Входной JSON)
Приложение должно каждые 200 мс опрашивать файл `/delta.json` (через `fetch('/delta.json?t=' + Date.now())`).
Формат JSON от C++ ядра:
{
  "_ts": 78957846,
  "add": [
    { "id": 1001, "ppid": 1, "flag": 0, "r": 0 }
  ],
  "upd": [
    { "id": 2006, "flag": 2, "r": 4 }
  ]
}

Правила обработки потока:
- Сравнивай `_ts` с последним обработанным `_ts`. Если `_ts` не изменился — игнорируй ответ (не перерисовывай граф впустую).
- Массив `add`: добавляет новые узлы (PID) и направленные рёбра `ppid -> id`. Если родительский узел (`ppid`) ещё не существует на графе (например, `pid: 1` или отрицательный `super_pid` контейнера) — создай для него виртуальный узел-якорь автоматически. Если узел с таким `id` уже есть — обнови его `ppid`, `flag` и `r`.
- Массив `upd`: обновляет `flag` и `r` у существующего узла на графе.

### 3. Предметная логика (Расшифровка полей)
1. Поле `flag` (Статус безопасности узла):
   - `0` = Clean (Изумрудно-зелёный `#10b981`) — штатный процесс
   - `1` = InRisk (Янтарно-жёлтый `#f59e0b`) — в зоне риска (потомок заражённого процесса)
   - `2` = Compromised (Ярко-красный `#ef4444`, пульсирующая обводка) — обнаружена атака
   - `3` = TEMP_LAGGING (Серый пунктир `#6b7280`) — ожидание родителя (out-of-order)
   - `4` = Orphan (Фиолетовый `#a855f7`) — процесс-сирота
2. Поле `r` (16-битная битовая маска сработавших правил безопасности, проверять `(r & (1 << bit)) !== 0`):
   - Бит 0 (1): `ReverseShell` (Обратная оболочка /sh)
   - Бит 1 (2): `Orphan` (Процесс без родителя)
   - Бит 2 (4): `DownloadExec` (Запуск из /tmp)
   - Бит 3 (8): `K8sTokenRead` (Чтение токена Kubernetes)
   - Бит 4 (16): `IpFanout` (Аномальная сетевая активность)
   - Бит 5 (32): `SysFileRewrite` (Модификация /etc)
   - Бит 6 (64): `TempDirExec` (Исполнение бинарника в /tmp)
   - Бит 7 (128): `Mass777` (Массовый chmod 777)
   - Бит 8 (256): `SuidRoot` (Повышение привилегий SUID)
   - Бит 9 (512): `ContainerEscape` (Побег из контейнера на хост)

### 4. Требования к интерфейсу (UI/UX)
1. **Верхняя панель (Header + KPI):**
   - Название: `R3E // Runtime Radar Resilience Engine` + индикатор статуса подключения (`LIVE` зелёный / `WAITING` жёлтый / `DEMO`).
   - 4 карточки-счётчика в реальном времени: Всего процессов, Clean (зелёные), In Risk (жёлтые), Compromised (красные).
   - Кнопки управления: «Очистить граф», «Авто-компоновка (Layout)» и переключатель **«Demo Mode (Симуляция атаки)»** — при включении Demo Mode интерфейс сам проигрывает пошаговый сценарий из 5 шагов (появление sshd, контейнера, out-of-order процесса, срабатывание ContainerEscape и распространение волны InRisk по детям), чтобы можно было демонстрировать интерфейс без запущенного C++ бэкенда.
2. **Центральная область (Граф Cytoscape.js):**
   - Иерархическая древовидная компоновка (`breadthfirst` или `dagre`), направленные стрелки от `ppid` к `id`.
   - Отрицательные `id` (суперкорни контейнеров) отображать в форме ромба или шестиугольника синего цвета с подписью `Container Root`.
   - На узлах отображать `PID: <id>`. При наведении — подсветка цепочки предков и потомков.
3. **Правая панель (Инспектор выбранного процесса):**
   - При клике на любой узел графа открывается карточка с деталями: PID, PPID, текущий статус с цветным бейджем, список всех сработавших правил (декодированных из битовой маски `r`) с кратким описанием угрозы, и таймстамп последнего обновления.

Сделай код чистым, модульным, без заглушек (чтобы всё сразу собиралось и запускалось через `npm run dev`).

### Обновление контракта JSON (Поддержка Live и History Mode)
Файл `/delta.json` теперь всегда содержит поле `"type"`, определяющее режим обновления холста:
1. Инкрементальное обновление в реальном времени (`"type": "graph_update"`):
   {
     "_ts": 1795454410200,
     "type": "graph_update",
     "add": [ { "id": 1001, "ppid": 1, "flag": 0, "r": 0 } ],
     "upd": [ { "id": 2006, "flag": 2, "r": 4 } ]
   }
   - Если интерфейс находится в режиме **LIVE**: применять `add` и `upd` поверх текущего графа, а также сохранять локальный снимок текущего состояния в буфер таймлайна браузера каждые 2 секунды (максимум 150 точек = 5 минут), чтобы ползунок работал даже в автономном режиме.
   - Если интерфейс находится в режиме **HISTORY (Пауза / Просмотр истории)**: **полностью игнорировать** входящие пакеты с `"type": "graph_update"`, чтобы живой поток не перезаписывал выбранный исторический кадр на холсте.

2. Полное восстановление среза (`"type": "snapshot_restore"`):
   {
     "_ts": 1795454400000,
     "type": "snapshot_restore",
     "add": [ { "id": 1001, "ppid": 1, "flag": 0, "r": 0 }, ... ]
   }
   - При получении пакета с `"type": "snapshot_restore"` (приходит при сдвиге ползунка истории или при нажатии кнопки возврата в LIVE): **полностью очистить холст Cytoscape.js** (`cy.elements().remove()`), отрисовать с нуля все узлы и рёбра из массива `add` и запустить авто-компоновку.

### Новый UI-элемент: Нижняя панель «Машина времени» (Time-Travel Scrubber)
Размести внизу экрана (под холстом графа) компактную панель управления временем:
1. **Переключатель режима:** Кнопка `● LIVE` (горит зелёным в реальном времени) и кнопка `⏸ HISTORY` (горит янтарным при просмотре истории).
2. **Ползунок времени (Slider):**
   - Диапазон: последние 5 минут с фиксированным шагом **2 секунды** (150 делений, от `-05:00` до `00:00`).
   - При перетаскивании ползунка интерфейс автоматически переходит в режим `HISTORY`, перестаёт применять новые `graph_update` дельты, отображает точное время выбранного среза (`HH:MM:SS`) и:
     * отправляет команду `POST /api/history` с телом `{"mode": "history", "ts": <выбранный_timestamp_ms>}` (с fallback на локальный буфер снимков браузера, если запущен без API-прослойки, чтобы ползунок гарантированно работал сразу из коробки!).
3. **Возврат в реальное время (Кнопка «Вернуться в LIVE»):**
   - При нажатии отправляет `{"mode": "live"}`, очищает историческое состояние на холсте, применяет самый свежий актуальный граф (из последнего `snapshot_restore` или актуального локального состояния) и возобновляет живое чтение `graph_update` дельт без дублирования узлов.
